# Cargo Admin — панель управления карго-компанией Китай → Таджикистан

CRM и операционная панель для карго: склады в Китае (Гуанчжоу, Иу, Урумчи, Кашгар), склады и пункты выдачи в Таджикистане (Душанбе, Худжанд, Куляб, Бохтар), рейсы траков через КПП Иркештам / Кульма / Карамык, посылки клиентов, чаты, финансы и тарифы.

Сервер сразу отдаёт **API для мобильного приложения клиентов** (вход по SMS-коду, трек-номера, чат, real-time). Документация: [`docs/CLIENT_API.md`](docs/CLIENT_API.md).

## Возможности

| Раздел | Что умеет |
|---|---|
| **Обзор** | KPI сети, карточка проблемного рейса с траком и линией маршрута, «Сводка операций» ассистента с причинами и предложенными действиями, live-карта, график рейсов (Gantt) с опозданиями |
| **Рейсы** | Список и карточка рейса: маршрут с КПП, ETA и опоздание к плану, план загрузки, документы (пломба, декларация, CMR/TIR), история событий, клиенты и посылки рейса, манифест CSV, смена статусов (загрузка → в пути → КПП → таможня → склад) |
| **Ассистент** | Находит рейсы под риском, предлагает смену маршрута (например, через Кульму вместо очереди на Иркештаме) с расчётом экономии, уведомляет клиентов о задержке, напоминает забрать посылки и оплатить долг. Любое действие — только после подтверждения сотрудника и пишется в журнал |
| **Live-трекинг** | Карта всех траков, фильтры (едут / стоят / тревоги), панель трака: водитель, скорость, топливо, груз, остаток пути, звонок и чат с водителем |
| **Поделиться трекингом** | Публичная ссылка `/t/<код>` для клиентов: карта и ETA без тарифов и данных других клиентов, настройки видимости и срок действия |
| **Посылки** | Приёмка на складе (скан трек-номера, автопривязка к клиенту, вес и габариты → цена по весу или объёму), неопознанные посылки «без кода», загрузка в рейс, выдача с оплатой, массовые действия и рассылки |
| **Клиенты** | Коды клиентов (DSH-, KHJ-, KLB-, BKT-), контакты, баланс, **адрес склада в Китае для Taobao / 1688 / Pinduoduo** с кнопкой «Копировать», посылки и платежи |
| **Чаты** | Клиенты (из приложения), водители, склады, команда. Real-time, быстрые ответы-шаблоны, контекст клиента и его посылок рядом с перепиской |
| **Склады** | Китай и Таджикистан: адреса (рус. + кит.), менеджеры, телефоны, режим работы, заполненность, входящие и исходящие рейсы |
| **Транспорт** | Траки (тент, рефрижератор, контейнер, фургон), водители, статусы, текущие рейсы |
| **Финансы** | Поступления по неделям, способы оплаты (наличные, Alif, Душанбе Сити, Корти Милли, перевод), должники, приём оплаты в USD / TJS / CNY |
| **Тарифы** | Тарифы по категориям ($/кг и $/м³, минимум, сроки), калькулятор для ответа клиенту |
| **Настройки** | Компания, курсы валют, бесплатное хранение, сотрудники и роли, журнал действий |

## Быстрый старт

Нужен **Node.js 22.13+** (база — встроенный `node:sqlite`, без нативных модулей).

```bash
npm install
```

```bash
npm run dev
```

Откройте http://localhost:5173. При первом запуске база заполняется демо-данными.

| Роль | Email | Пароль |

Сбросить базу к демо-данным:

```bash
npm run seed
```

> Перед запуском для реальной работы смените пароли сотрудников и название компании (Настройки), удалите демо-данные (`data/cargo.db`) и создайте свои склады, тарифы и пользователей.

## Продакшен

```bash
npm run build
```

```bash
npm start
```

Один процесс отдаёт и API, и собранную админку на `PORT` (по умолчанию 3001). Поставьте перед ним nginx/Caddy с HTTPS.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3001` | Порт сервера |
| `DB_PATH` | `data/cargo.db` | Файл базы SQLite (делайте бэкапы) |
| `CORS_ORIGIN` | `*` | Домен(ы) клиентского приложения |
| `NODE_ENV` | — | `production` скрывает SMS-код в ответе API |

## Как устроено

```
server/
  index.ts          — Express: API + раздача собранной админки
  db.ts             — SQLite (node:sqlite), схема таблиц
  geo.ts            — города, КПП, маршруты Китай → Таджикистан
  domain.ts         — статусы, тарифы, уведомления, чаты, каскад статусов рейс → посылки
  assistant.ts      — «Ассистент операций»: риски, смена маршрута, напоминания
  sim.ts            — симуляция GPS (замените на реальный трекер)
  realtime.ts       — Server-Sent Events для админки и приложения клиента
  seed.ts           — демо-данные
  routes/           — ops (рейсы, склады, транспорт), crm (клиенты, посылки, финансы),
                      chat, client (API приложения), public (трекинг), auth
web/src/
  pages/            — страницы админки
  components/       — UI-кит, карта (Leaflet), трак, линия маршрута, график рейсов, модалки
docs/CLIENT_API.md  — API для мобильного приложения клиентов
```

Жизненный цикл посылки: **Ожидается** (клиент добавил трек в приложении) → **На складе в Китае** (приёмка, вес, цена) → **В пути** (рейс отправлен) → **Таможня** → **Готов к выдаче** (рейс принят на склад, клиент получает сообщение с адресом и суммой) → **Выдан**. Клиенту автоматически уходят сообщения на ключевых этапах.

## Что подключить дальше

- **SMS** для входа в приложение — провайдер (например, OsonSMS) в `server/routes/client.ts`, функция `request-code`.
- **GPS** — вместо `server/sim.ts` принимать координаты от трекеров (Wialon, GPS-Trace) или из приложения водителя.
- **Оплата онлайн** — Alif / Душанбе Сити по их API, запись в `payments`.
- **Telegram-бот** для уведомлений клиентам — та же функция `messageClient`.
- **PostgreSQL** — при росте нагрузки; SQL в проекте стандартный.
- **Таджикский язык** интерфейса и приложения.
